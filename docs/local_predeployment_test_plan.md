# 로컬 배포 전 기능·성능 테스트 계획

## 1. 목적

로컬 버전이 감사보고서 관련 기능 외에 제공하는 모든 DART 조회 기능을 정상적으로 수행하는지 확인하고, 각 결과를 Markdown 또는 Excel 파일로 직접 생성할 수 있는지 검증한다. 또한 배포 전에 응답시간, 실패율, 반복 실행 안정성, 메모리 사용량이 최소 합격 기준을 만족하는지 측정한다.

## 2. 테스트 범위

### 공통 탐색 기능

- `search_companies`
- `list_report_filings`
- `list_report_attachments`
- `list_report_sections`
- `get_report_sections`

### 감사 관련 항목을 제외한 데이터 기능

- DS001 기업정보: `get_company_profile`
- DS002 정기보고서 주요정보: 감사 관련 3종을 제외한 25종
- DS003 재무정보: `get_financial_statements`, `get_major_accounts`, `get_financial_indicators`
- DS004 지분공시: `major_holding`, `insider_ownership`
- DS005 주요사항보고: 지원 유형 36종
- DS006 증권신고서: 지원 유형 6종

DS002에서 제외하는 감사 관련 항목은 `audit_opinion`, `audit_service_contract`, `non_audit_service_contract`이다.

### 파일 생성 기능

- `export_report_markdown`
- `export_report_excel`

현재 두 파일 생성 도구는 선택한 첨부문서 전체를 입력으로 받는다. DS001부터 DS006까지의 개별 조회 결과를 입력으로 받는 공통 파일 생성 도구는 별도로 존재하지 않으므로, 이 차이를 기능 테스트에서 배포 적합성 항목으로 판정한다.

## 3. 실행 순서

1. 환경과 설정 확인
2. `Pytest -v` 전체 회귀 테스트
3. 정적 검사와 패키지 빌드
4. 로컬 MCP 도구 15개 등록 확인
5. 감사 관련 항목을 제외한 전체 기능 계약 테스트
6. 실제 OpenDART 호출로 대표 정상 시나리오 확인
7. Markdown·Excel 실제 파일 생성과 내용 검증
8. 반복 호출 성능과 메모리 측정
9. 배포 가능 여부 판정

## 4. 기능 합격 기준

- 전체 자동화 테스트가 통과한다.
- 로컬 MCP에 조회 도구 13개와 파일 생성 도구 2개가 모두 등록된다.
- 지원하는 모든 비감사 유형이 유효한 입력으로 인식된다.
- 정상 호출은 `Result.ok=true`, 실패 호출은 구조화된 오류를 반환하며 처리되지 않은 예외가 없다.
- 반환 건수와 실제 행 수가 일치한다.
- 빈 데이터는 문서화된 경고와 함께 정상 응답하거나 문서화된 오류를 반환한다.
- Markdown 파일은 UTF-8 텍스트로 열리고 원문 구역 순서를 유지한다.
- Excel 파일은 열 수 있고, 시트·셀·병합 범위 검증을 통과한다.
- 개별 조회 결과의 Markdown 또는 Excel 직접 산출 여부가 기능별로 명확히 판정된다.

## 5. 임시 성능 합격 기준

사용자 지정 SLA가 없으므로 아래 값을 배포 전 최소 기준으로 사용한다. 측정 결과와 함께 기준 자체도 최종 보고서에 명시한다.

| 구분 | 최소 기준 |
| --- | --- |
| 자동화 테스트 | 실패 0건 |
| 대표 실제 조회 | 실패율 0%, 처리되지 않은 예외 0건 |
| 단일 OpenDART 조회 | 반복 측정 p95 10초 이하 |
| 복수 유형·복수 회사 조회 | 반복 측정 p95 30초 이하 |
| Markdown·Excel 최초 생성 | 각각 120초 이하 |
| 동일 원문 파일 재사용 | 각각 5초 이하 (정정공시 경유 공시는 10초 이하) |
| 로컬 프로세스 최대 메모리 증가 | 512 MiB 이하 |
| Vercel 함수 제한 대비 | 모든 단일 작업이 300초 제한의 50% 이내 |

재사용 기준에 정정공시 예외를 둔 이유는 다음과 같다. 같은 인자로 두 번째 요청이 들어오면 서버는
"이미 만들어 둔 파일이 정말 같은 원문인가"를 원문 지문(SHA-256)으로 확인해야 하고, 그러려면 원문을
다시 받아야 한다. 최초 공시가 정정공시로 대체된 종목은 이 확인 경로에 원공시 조회가 한 단계 더 붙어
같은 작업이 구조적으로 더 걸린다(2026-09-06 측정: 정정공시를 경유하지 않는 4개사 Excel·Markdown
2.5~3.6초, 경유하는 1개사 Excel 8.4초·Markdown 8.6초). 값의 정확성·최초 생성·조회 도구에는
영향이 없으므로 이 초과는 배포 차단 사유로 보지 않는다.

`p95`는 측정값의 95%가 그 시간 안에 끝난다는 뜻이다. 표본이 적은 로컬 사전 점검에서는 최대값도 함께 보고하며, p95는 정식 부하시험 전의 참고치로 취급한다.

## 6. 결과 판정

- **통과**: 기능 기준과 성능 기준을 모두 만족한다.
- **조건부 통과**: 핵심 조회는 정상이나 일부 유형의 데이터 부재, 외부 API 변동, 또는 비핵심 성능 경고가 있다.
- **배포 차단**: 자동화 테스트 실패, 지원 유형 호출 실패, 파일 손상, 처리되지 않은 예외, 또는 성능 기준 초과가 있다. 성능 기준은 §5 표의 예외를 적용한 뒤 판정한다.
- **기능 미지원**: 조회는 정상이나 해당 조회 결과를 Markdown·Excel로 직접 저장하는 제품 기능이 없다. 이는 테스트 실패가 아니라 현재 제공 범위의 결손으로 별도 표시한다.
