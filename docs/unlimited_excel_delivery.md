# 대용량 Excel 데이터 전달 계약

이 문서는 일반 조회 한도를 넘는 데이터를 원격에서 여러 응답으로 받는 방법과 로컬 `.xlsx` 파일로 내보내는 기준을 설명합니다.

## 원격 페이지 조회

원격 서버의 `load_excel_page`는 13개 조회 영역 중 하나를 실행하고 결과를 행과 열로 정규화합니다. **페이지**는 한 번의 도구 호출로 반환되는 연속된 행 묶음이고, **커서(cursor)**는 다음 묶음의 시작 위치와 원본 상태를 확인하는 서명된 문자열입니다.

첫 요청 예시는 다음과 같습니다.

```json
{
  "request": {
    "domain": "list_report_filings",
    "arguments": {
      "corp_code": "00126380",
      "report_kind": "audit"
    },
    "page_size": 1000,
    "cursor": null
  }
}
```

응답의 `next_cursor`가 문자열이면 클라이언트는 다음 규칙으로 즉시 다시 호출해야 합니다.

1. `domain`, `arguments`, `page_size`를 그대로 유지합니다.
2. `cursor`만 직전 응답의 `next_cursor`로 바꿉니다.
3. 새 `rows`를 기존 행 뒤에 추가합니다.
4. `next_cursor=null`이 될 때까지 반복합니다.

각 페이지에서 `page_index`는 0부터 1씩 증가하고 `offset`은 해당 페이지 첫 행의 전체 결과 내 위치입니다. 모든 페이지의 `returned_rows` 합은 `total_rows`와 같아야 하며, 인접 페이지 사이에 누락이나 중복이 없어야 합니다.

## 3.5MB 응답 기준

`3,500,000`바이트는 전체 사용자 요청의 누적 한도가 아니라 `load_excel_page` 한 번이 만드는 최종 JSON-RPC HTTP 응답의 한도입니다. 모든 성공·오류 응답은 정확히 `3,500,000`바이트 미만이어야 합니다.

이 애플리케이션 기준은 [Vercel Functions의 요청·응답 본문 4.5MB 제한](https://vercel.com/docs/functions/limitations)보다 여유를 둔 값입니다. Vercel의 실행시간·메모리·함수 호출량 제한과 OpenDART의 이용량 제한은 별도이며 페이지를 나누어도 없어지지 않습니다.

크기 계산에는 행 데이터뿐 아니라 다음 항목도 포함합니다.

- MCP 응답의 텍스트 내용과 구조화된 내용
- JSON 문자 이스케이프
- 열 이름, 경고, 출처 정보
- JSON-RPC 포장과 요청 ID

`page_size`의 기본값과 최댓값은 모두 1,000행입니다. 후보 응답이 한도에 가까우면 서버가 실제 반환 행 수를 자동으로 줄입니다. 이때 행 하나는 둘로 나누지 않습니다.

- 한 행만으로 한도를 넘으면 `row_exceeds_page_budget` 오류가 발생합니다.
- 행이 없어도 열·경고·출처 정보가 한도를 넘으면 `dataset_schema_exceeds_page_budget` 오류가 발생합니다.
- 두 오류 모두 로컬 `export_query_excel` 사용을 안내합니다.

커서는 요청과 페이지 크기에 묶여 있으므로 다른 입력에 재사용할 수 없습니다. 각 후속 페이지는 원본을 한 번 다시 조회합니다. 원본이 바뀌거나 커서 위치가 유효하지 않으면 커서 없이 첫 페이지부터 다시 시작해야 합니다.

애플리케이션 차원의 전체 행 수 상한은 없습니다. 그러나 OpenDART의 이용량·요청 범위 제한과 배포 환경의 실행시간·메모리·호출량 제한은 각 페이지에 계속 적용됩니다. 따라서 매우 큰 결과는 페이지 수만큼 원본 조회와 서버 호출을 사용합니다.

## 로컬 전체 결과 내보내기

로컬 서버의 `export_query_excel`은 `domain`과 `arguments`만 받습니다. 파일명, 경로, 페이지 크기는 사용자가 지정하지 않습니다.

저장 폴더는 다음 순서로 정합니다.

1. `DART_MCP_OUTPUT_DIR`
2. 설정이 없으면 프로젝트 기준 폴더의 `output`

파일명은 `<domain>`에 요청 인자를 이어 붙여 만듭니다 — 예: `get_financial_statements_00126380_2025_11011_CFS.xlsx`. 같은 폴더에 연도만 바꿔 여러 번 내보내도 파일을 열지 않고 구분할 수 있습니다.

- 인자는 도메인 인자 모델의 필드 순서로 붙습니다.
- 목록 인자(`corp_codes`, `topics`, `event_types` 등)는 앞의 3개를 `-`로 잇고 나머지는 `외N`으로 표기합니다(`00126380-00164779_...`). 전체 목록은 `metadata` 시트에 있습니다.
- 각 인자는 40자까지만 이름에 들어가고, 파일명 전체는 Windows 제한에 맞춰 잘립니다. 예약어와 사용할 수 없는 문자는 `_`로 치환합니다.
- 이름이 겹치면 `_2`, `_3` 순서로 번호를 붙이며 기존 파일을 덮어쓰지 않습니다. 이름은 잘릴 수 있으므로 **같은 이름이 반드시 같은 요청을 뜻하지는 않습니다** — 정확한 요청은 `metadata` 시트의 `argument.*` 행과 `request_fingerprint`로 확인하세요.

`metadata` 시트에는 요청 인자가 `argument.<이름>` 행으로 하나씩 펼쳐 기록됩니다(목록·중첩 값은 표준 JSON 문자열). 결과에는 절대경로, 파일명, 데이터셋 식별값, 전체 행 수, 시트 이름이 포함됩니다.

시트 순서는 `data`, `data_2`, …, `metadata`, `warnings`입니다. 데이터 시트 하나에는 헤더 1행과 데이터 최대 1,048,575행을 저장합니다. Excel의 열 한계인 16,384열을 넘으면 `excel_column_limit_exceeded` 오류가 발생하고 파일을 게시하지 않습니다.

## 금액 열 숫자 변환

OpenDART는 금액도 문자열로 돌려줍니다. 그대로 두면 Excel에서 SUM·정렬·피벗이 동작하지 않으므로, 아래 금액·지표 필드는 **정규화 단계에서 숫자로 읽습니다.** 이 변환은 원격 `load_excel_page` 응답과 로컬 파일에 동시에 적용되므로 두 결과의 값은 여전히 동일합니다.

| 대상 필드 | 나오는 도구 |
| --- | --- |
| `thstrm_amount`, `thstrm_add_amount`, `frmtrm_amount`, `frmtrm_q_amount`, `frmtrm_add_amount`, `bfefrmtrm_amount` | `get_financial_statements`, `get_major_accounts` |
| `idx_val` | `get_financial_indicators` |

- 변환 대상은 **필드 이름으로만** 정합니다. `corp_code`(`00126380`), `rcept_no`(`20260310002820`), `reprt_code`, `stlm_dt` 같은 식별자도 전부 숫자로만 이루어진 문자열이므로, 값의 생김새로 판정하면 앞자리 0이 사라지거나 접수번호가 천 단위로 표시됩니다. 목록에 없는 필드는 지금까지와 같이 문자열로 남습니다.
- 한 열은 **그 열의 모든 값이 숫자로 읽힐 때만** 숫자가 됩니다. `-` 같은 표시가 한 칸이라도 섞여 있으면 열 전체가 문자열로 남아 한 열 안에 타입이 섞이지 않습니다.
- 빈 값은 판정에서 제외되고 빈 값 그대로 남습니다. 없는 금액이 0으로 바뀌지 않습니다.
- 쉼표(`1,234,567`)와 회계식 괄호 음수(`(112,071)`)를 읽습니다. `26,34`처럼 천 단위 규칙에 맞지 않는 표기는 숫자가 아닙니다.
- 숫자가 된 열에는 표시 서식이 붙습니다. 정수만 있으면 `#,##0`, 소수가 있으면 그 열에서 관측된 최대 소수 자릿수만큼 `#,##0.00`(최대 6자리)입니다.
- 조회 도구 13종이 각자의 응답에서 값을 원문 그대로 전달하는 계약은 그대로입니다. 이 변환은 `export_query_excel`과 `load_excel_page` 두 도구에만 적용됩니다.
- 원 단위 금액이 `2**53`(약 9,007조)을 넘으면 아래 정밀도 규칙이 함께 적용됩니다. 이때 값은 **경고 없이** 가장 가까운 배정밀도 실수로 바뀌므로 끝자리가 달라질 수 있습니다(문자열로 두던 이전 동작과 다른 점입니다). 국내 상장사 원 단위 총액은 이 한도의 10분의 1 수준이지만, JSON을 읽는 쪽이 큰 정수를 배정밀도 실수로 처리하면(브라우저 자바스크립트 등) 한도 아래에서도 정밀도가 줄 수 있습니다.

## XLSX 값 보존 범위

로컬 파일은 분석과 열람용입니다. 원격 JSON과 모든 값의 타입·정밀도가 완전히 같은 보관 형식을 보장하지 않습니다.

- 불리언 `true`·`false`는 숫자보다 먼저 판별해 불리언 셀로 저장합니다.
- 절댓값이 `2**53` 이하인 정수는 정수로 저장합니다.
- 더 큰 정수는 유한한 실수로 변환되므로 Excel에서 정밀도가 줄어들 수 있습니다.
- 실수는 저장 후 파일을 다시 열어 값과 타입을 검증합니다.
- 문자열은 먼저 32,767자로 자르고, 저장할 부분에 허용되지 않는 XML 제어문자가 없는지 검사합니다.
- 빈 문자열은 파일을 다시 열었을 때 `None`으로 읽힐 수 있습니다.
- 정수값을 가진 실수는 다시 열었을 때 정수로 읽힐 수 있습니다.
- 음수 0은 다시 열었을 때 부호가 사라질 수 있습니다.
- 모든 문자열은 문자열 셀과 `quotePrefix=True`로 저장합니다. 따라서 `=`, `+`, `-`, `@`로 시작해도 수식으로 실행되지 않습니다.

중첩 객체와 배열은 키가 정렬된 표준 JSON 문자열로 셀에 저장하며 배열 순서는 유지합니다. 원격 페이지와 로컬 파일 모두 원본 행 순서를 유지합니다.

## 인증과 비밀값 관리

원격 도구 호출의 API 키 우선순위는 다음과 같습니다.

1. 첫 번째 비어 있지 않은 `X-OpenDART-API-Key`
2. 첫 번째 올바르고 비어 있지 않은 `Authorization: Bearer` 값
3. URL에서 마지막 `?key=` 값을 한 번 해석한 뒤 앞뒤 공백을 제거한 값

헤더 두 방식 중 하나를 권장합니다. URL `?key=` 방식은 요청 헤더를 설정할 수 없었던 일부 Claude 연결 환경에서 관찰된 호환 경로이며, 해당 공급자가 계속 지원한다고 보장하지 않습니다. URL은 클라이언트 설정과 접속 기록에 남을 가능성도 더 큽니다.

키가 노출되었거나 URL 기록 여부를 확신할 수 없다면 OpenDART에서 기존 키를 폐기하거나 재발급하고, 클라이언트 설정·환경변수·배포 비밀값을 새 키로 교체해야 합니다. API 키는 응답, 커서, 지문, 데이터셋 식별값, 오류 상세정보에 포함되지 않습니다.

## 오류 후 다시 시작하는 경우

다음 오류는 기존 커서를 버리고 `cursor=null`로 첫 페이지부터 다시 호출해야 합니다.

- `invalid_cursor`
- `cursor_schema_mismatch`
- `cursor_request_mismatch`
- `cursor_page_size_mismatch`
- `source_changed`
- `cursor_position_invalid`

`row_exceeds_page_budget`와 `dataset_schema_exceeds_page_budget`는 같은 원격 요청을 반복해도 해결되지 않습니다. 이 경우 로컬 `export_query_excel`을 사용합니다.
