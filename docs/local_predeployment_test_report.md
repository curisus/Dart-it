## 4. MD/XLSX 산출 가능 여부

| 입력 데이터 | Markdown | Excel | 판정 |
| --- | --- | --- | --- |
| 선택한 보고서 첨부문서 | 지원 | 지원 | 기존 기능 |
| DS001 기업정보 | 미지원 | 미지원 | 공통 변환기 없음 |
| DS002 비감사 주요정보 25종 | 미지원 | 미지원 | 공통 변환기 없음 |
| DS003 재무정보 | 미지원 | 미지원 | 공통 변환기 없음 |
| DS004 지분공시 | 미지원 | 미지원 | 공통 변환기 없음 |
| DS005 주요사항보고 | 미지원 | 미지원 | 공통 변환기 없음 |
| DS006 증권신고서 | 미지원 | 미지원 | 공통 변환기 없음 |

현재 `export_report_markdown`과 `export_report_excel`의 입력은 접수번호와 첨부문서 식별자뿐이다. 조회 도구의 `Result` 데이터를 받는 입력이나 변환 경로가 없다. 따라서 외부 프로그램이 Result를 별도로 변환할 수는 있어도, 현재 제품 기능만으로는 “감사보고서 외 모든 솔루션을 MD/XLSX로 산출”할 수 없다.

## 5. 배포 전 남은 위험

1. DS001~DS006용 공통 Markdown·Excel 변환 기능이 없다.
2. 이번 성능 시험은 동시성 1의 로컬 사전 점검이다. 다중 사용자 동시 호출과 장시간 부하는 측정하지 않았다.
3. 실제 증권신고서 6종은 선택 회사·기간에 행이 없어 정상 빈 결과 경로만 확인했다. 양수 데이터 매핑은 자동화 테스트로 검증했지만, 각 유형의 실제 라이브 양수 표본은 별도 회사 선정이 필요하다.
4. 실제 첨부문서 파일 생성은 감사·검토보고서 경로에 속하므로 이번 비감사 범위의 라이브 호출에서 제외했다. 파일 생성기 자체는 고정 입력 기반 테스트 57건으로 검증했다.
5. Markdown 기존 파일 재사용은 메타데이터 일치 중심이므로, 본문이 외부에서 훼손된 기존 파일을 재사용할 위험을 별도로 검토할 필요가 있다.

## 6. 권고

- 배포 목표가 구조화된 DART 조회라면 현재 성능과 안정성은 최소 배포 기준을 충족한다.
- 배포 목표가 모든 비감사 솔루션의 MD/XLSX 파일 제공이라면 공통 파일 변환 기능을 구현하고 다시 테스트해야 한다.
- 기존 첨부문서 파일 기능의 성능을 최종 통과로 판정하려면 실제 분기·반기 원문에서 최초 생성시간, 재사용시간, 최대 메모리, 원문 대사를 측정해야 한다.
- 다음 성능 단계에서는 동시 사용자 수를 정한 뒤 콜드 5회, 웜 20회, 동시성 부하, 30분 이상 반복을 추가하는 것이 적절하다.
