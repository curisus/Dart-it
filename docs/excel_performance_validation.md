# Excel 성능 검증 기록

이 문서의 수치는 2026-08-28에 동일한 Windows 장비에서 직접 관찰한 개발 검증 결과입니다. 서비스 수준 협약(SLA)이나 모든 장비에서의 처리시간 보장이 아닙니다. OpenDART 네트워크 호출 시간은 측정에서 제외했습니다.

## 재현 명령

```powershell
uv sync --frozen
uv run --script scripts/benchmark_excel_pipeline.py --runs 3 --rows 10000 --columns 20 --output benchmark.json
```

부모 프로세스는 각 측정을 새 Windows 프로세스로 시작합니다. 각 자식 프로세스는 같은 규칙으로 만든 10,000행×20열 자료에 대해 실제 운영 코드 경로를 실행합니다.

- 정규화: 셀 정규화와 요청·원본·데이터셋 지문 계산
- 페이지 선택·전송 직렬화: 이미 정규화된 자료의 페이지 선택과 MCP 두 전송 형식 크기 계산
- XLSX 생성: 임시 파일 작성, 다시 열어 검증, 하드링크 게시까지 포함
- 무상태 페이지 처리: 원본 호출을 제외한 정규화와 페이지 선택·직렬화
- 메모리: Windows 프로세스의 최대 작업 집합 크기(`PeakWorkingSet64`)

## 전체 개발 검증 명령

```powershell
uv sync --frozen
uv run ruff check .
uv run mypy --strict src tests
uv run pytest -v
uv build
```

위 명령은 코드·타입·테스트·배포 패키지 생성의 로컬 검증입니다. 실제 OpenDART 키, Vercel Preview, Claude Connector, Claude for Excel을 사용하는 외부 검증은 별도 배포 승인 단계에서 수행해야 합니다. 이 기록은 외부 검증을 대신하지 않습니다.
